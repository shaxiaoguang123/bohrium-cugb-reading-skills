description: 将真实论文转成按原章节排列的阅读笔记、证据索引和可比较的研究卡片。
---
先按任务范围枚举论文和附件。用原文目录与正文标题重建层级，标记页码偏移、附录及跨页续节；若无标题，按实际论证转折切分并标明“编者分段”。固定每段 ID = 文献短名/物理页/段序。论文综述他人的研究与作者自己的发现分别标注。
以章节为单位提取原子笔记。每条含章节路径、研究问题、条目类型、陈述、成立条件、证据短引与定位、关键词。数据写明来源、样本及划分；方法写变量、测量和比较条件；结果必须绑定指标、单位、分母、基线与不确定性。若题面只需指定章节，以该范围为准。表格结果的定位包括行名、列名和注脚。由正文回查表格；冲突并列记录。把原文限制与读者推断分别放置。
输出两种视图：原章节树下的可读 Markdown，以及按记录 ID 索引的 JSON 条目。建立问题→方法→结果→局限的引用边，指向同一批 ID。多论文比较以同一问题和指标为行，保留各文献口径，不直接比较不同样本或单位。最后给出可检索的主题/方法/数据关键词索引。逐章节检查是否有条目或明确不适用原因；逐条反查锚点。
示例：输入一段“Under setting B, median error was 3 mm.”，要求结果笔记。示意输出 {"kind":"finding","claim":"中位误差为 3 mm","condition":"setting B","anchor":"示例文档/结果/段1","keywords":["误差","中位数"]}。用真实文档替换示例，缺失的样本数记未报告。

## 运行与交付
读取 /input/case.json、task.md 及引用的实际材料，把每个 output_contract 字段映射到本次要生成的内容。以文件内容校正题签。中间文件留在 /app/work，先保存可核验的部分结果，再补全。最终写 /app/output/result.json，保留原 case_id 和契约要求的名称、层次、类型，另存案例要求的可编辑产物。Office 类产物需用可用的渲染器实际导出 PDF/PNG 供检查。
每条关键结果附文件名、页/节/行或图表号、最短可核对原文；推断与原文分开。缺失、未报告、材料冲突和工具失败分别标记，列出已完成范围、失败位置及下一步。记录实际变更与证据，不估算对照得分。检查 JSON 可解析、所有引用的文件存在、打开最终产物并抽核首尾及高风险项。运行 python3 /skills/weekly-skill/check.py /input/case.json /app/output/result.json 检查身份及标准 JSON Schema 的必需键；非标准契约逐项人工核对。依赖 Python 3.8+ 标准库。

编译并反查笔记：从原始文档单独提取 passages.json，键为唯一原文定位，值含 section 与 text（保持原章节顺序）。将整理出的 notes.json 写成数组，每条含 id、anchor、quote、claim、keywords，以及对该条适用的条件/方法/结果字段。运行 python3 /skills/weekly-skill/notebook.py passages.json notes.json /app/work/notebook。notes.md 按章节汇集，index.json 保留完整笔记、主题索引、未覆盖章节及无法在指定段落复现的引文。逐项处理 review：同一句在别处出现不能证明当前锚点正确。若 OCR 换行或跨页导致失配，对照页图后拆成多条证据，保留原材料标识。复核后将实际产物复制到 /app/output，与 case 的字段逐项映射。
