---
name: literature-graph
description: 从多篇论文生成可查询、可追溯的实体关系图，处理别名、条件与相互冲突的证据。
---
将案例问题先转为查询槽位（节点类型、谓词、边的限定条件、所需返回字段）。使用案例自带本体；缺少本体时从问题选择最小类型表，例如 Material、Method、Dataset、Metric、Finding，明确每种边的方向和允许端点。逐篇独立抽取名称提及，记录原文、局部定义、文档版本、页段及证据。每个节点至少一个可定位提及。
实体消歧依次用外部标识符、文内明确定义、全称加类型及上下文。弱匹配只建候选，保留原拼写、别名和合并依据。同一缩写跨学科分别建节点。同一方法的版本、同一材料的处理条件另记属性。逐句提取有谓词证据的边，记录主体、客体、比较基准、方向、测量条件、证据及直接/转述/假设属性。只有共现时保留提及。冲突边分来源并存，按样本/版本/实验设置解释可比性。
以 UTF-8 导出 nodes、edges、alias decisions、未解析项和问题答案。每个答案附实际匹配的节点、边 ID、路径和证据。多跳答案不能把路径压成未经支持的因果边。运行 python3 /skills/weekly-skill/query.py graph.json NODE 查询入/出边；该内部格式可映射到案例要求的 CSV、JSON-LD 或 GraphML。抽查孤立节点、重复有向边、悬空端点、别名碰撞与无证据关系。
示例输入“方法 M 在数据集 D 上评测”。示意图含 M/evaluatedOn/D 和证据“示例段1”；查询 D 返回 M，不能据此写出 M 的性能排名。

## 运行与交付
读取 /input/case.json、task.md 及引用的实际材料，把每个 output_contract 字段映射到本次要生成的内容。以文件内容校正题签。中间文件留在 /app/work，先保存可核验的部分结果，再补全。最终写 /app/output/result.json，保留原 case_id 和契约要求的名称、层次、类型，另存案例要求的可编辑产物。Office 类产物需用可用的渲染器实际导出 PDF/PNG 供检查。
每条关键结果附文件名、页/节/行或图表号、最短可核对原文；推断与原文分开。缺失、未报告、材料冲突和工具失败分别标记，列出已完成范围、失败位置及下一步。记录实际变更与证据，不估算对照得分。检查 JSON 可解析、所有引用的文件存在、打开最终产物并抽核首尾及高风险项。运行 python3 /skills/weekly-skill/check.py /input/case.json /app/output/result.json 检查身份及标准 JSON Schema 的必需键；非标准契约逐项人工核对。依赖 Python 3.8+ 标准库。

题目要求路径或跨论文关联时，执行 python3 /skills/weekly-skill/paths.py graph.json 起点 终点 --hops 2。节点含 id、label、aliases（数组）；边含 source、target、predicate、evidence，具体证据应含原文与定位。查询优先解析精确 ID，再匹配显示名称或别名；同名候选须按类型与来源消歧。逐条返回有向简单路径及各边完整条件、原始证据。反向问题先明确边方向；如需查入边使用 query.py。结果末行报告匹配数与截断标志；对截断图缩小语料、谓词或范围后查询。回答时引用边级来源；路径存在只能支持关联查询，验证共享实验条件后才做联合比较。
